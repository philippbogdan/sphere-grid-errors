# Reproduce the results

Run commands from this repository's root. All generated files stay under `build/`; the large fields are not bundled or hosted.

## Check the saved evidence

```sh
python3 -S scripts/reproduce.py
```

No installation, download or simulation is needed. This checks evidence and figure hashes, requires unique record selectors, rebuilds the archived headline arithmetic and verifies the new field summaries against the bundled metrics. It recovers 5.33265185658x for cones and 2.81015510331x for controls at day 10. Use `--write` only to rewrite the six derived archived files from the unchanged evidence.

## Install

Use Python 3.12, with `git` and `gfortran` on `PATH`:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

This installs the solver at revision `376f20bda091acee109abd183bc4684080288fc9`. The reference fetch verifies the NCAR archive hash before compilation; its [research and education terms](THIRD_PARTY.md) apply. Set `FC` to select a different Fortran executable.

## Rerun the headline experiment

```sh
python scripts/rerun.py references --which T85
python scripts/rerun.py relax --configuration visual --end-day 10
```

The reference goes to `build/stswm/runs/T85dt45/`; the three solver runs write scores and snapshots to `build/runs/{none,cones,controls}.{json,npz}`. T85 uses 45 s steps and two-hourly output. Only T85 is required; if T213 is present, the runs also score against it.

A clean installation reproduced the archived day-10 scores to within 8e-13 relative. T85 compilation and execution took 99.7 s, followed by about 31 s per solver run:

| Run | New l2 against T85 | Archived l2 |
|---|---:|---:|
| Main | 2.625413742822696e-3 | 2.625413742820644e-3 |
| Cones | 4.923279849184316e-4 | 4.923279849184393e-4 |
| Control | 9.342593722793704e-4 | 9.342593722788615e-4 |

To rerun all 12 archived treatments, use `--configuration all --end-day 10` instead. Indices 0 through 11 select individual entries in the [configuration table](docs/METHOD.md#relaxation).

## Regenerate the fields and visuals

Start with a fresh `build/` directory for this alternative path. Existing numerical runs are not overwritten; `rerun.py --build DIR` selects another root, with corresponding input/output paths accepted by `prepare_fields.py` and `render.py`.

```sh
python -m pip install -r requirements-figures.txt
python scripts/rerun.py references
python scripts/rerun.py relax --configuration visual --end-day 14
python scripts/prepare_fields.py
python scripts/render.py all
```

Install FFmpeg with `libx264` and `ffprobe` on `PATH` for movies, and gifsicle for the inline GIF. `FFMPEG`, `FFPROBE` and `GIFSICLE` select their executables. All visuals use Matplotlib's bundled DejaVu Sans.

| Stage | Produces | Measured time |
|---|---|---:|
| T85 reference | 256 by 128 fields, 45 s steps | About 2 min |
| T213 reference | 640 by 320 fields, 22.5 s steps | 4,695 s, about 78 min |
| Each M = 128 solver run | Day-14 scores and 169 snapshots | About 35 s |
| Field preparation | Six NPZ files, metrics, validation and hashes in `build/fields/` | A few minutes |

Both references span 336 hours with two-hourly output and together occupy about 0.96 GB. Actual solver snapshot times are retained. The six prepared NPZ files total about 114 MB; [field-assets.json](data/field-assets.json) identifies the exact inputs used for the delivered figures. Regenerated bytes can differ with numerical libraries and compression; compare scores as well as hashes.

`render.py all` writes three PNG/SVG chart pairs, two movies, the day-10 hero poster and the correction GIF to `build/figures/`, then checks metadata, encoding and sampled frames in `build/qa/`. Temporary encoding frames use `build/render/` and are removed afterwards. Rendering time is additional to the measured numerical times above. To render only the archived charts, use `python scripts/render.py charts`; `check`, `posters`, `movies`, `gif`, `qa` and `manifest` run individual stages.

The checked field runs reproduce archived T85 scores to about 2e-9 relative. The main T213 field scores agree with `tc6_series.jsonl` within 6e-6 relative at the recorded days from 1 to 14. Full-precision T85 scores and float32 field scores remain distinct in [visual-runs.json](data/visual-runs.json); [FIELDS.md](docs/FIELDS.md) documents the transformations and checks.

## Regenerate only the inline GIF

With FFmpeg and gifsicle installed, this uses the bundled MP4 without fields, simulation or Python packages:

```sh
python3 -S scripts/render.py gif
```

It writes `build/figures/relaxation-fields.gif` and its recipe to `build/qa/relaxation-fields-gif.json`. Use `--input PATH` for another correction MP4 or `--out DIR` for another destination. The full `all` stage uses its newly rendered MP4.

The recipe takes 43 frames, one per eight simulated hours (`h = 0, 8, ..., 336`), from movie time `t = 1 + 21*h/336 + 0.06` seconds. It scales each to 1,000 pixels wide with Lanczos filtering, builds a 128-colour palette at four frames/s without dithering, then applies gifsicle's lossy optimisation. These are the exact encoding commands, with `t` and `NNN` replaced for each frame:

```sh
ffmpeg -ss t -i relaxation-fields.mp4 -frames:v 1 -vf scale=1000:-1:flags=lanczos frames/NNN.png
ffmpeg -framerate 4 -i frames/%03d.png -vf "split[a][b];[a]palettegen=max_colors=128:stats_mode=full[p];[b][p]paletteuse=dither=none:diff_mode=rectangle" raw.gif
gifsicle -O3 --lossy=140 --loopcount=forever raw.gif -d 25 '#0-41' -d 200 '#42' -o relaxation-fields.gif
```

Frames 0 through 41 last 0.25 s each; frame 42 lasts 2 s. The 12.5-second GIF loops forever. Use a recent FFmpeg build and gifsicle 1.9x; encoded bytes can vary between versions. GIF compression changes pixel values slightly; the MP4 remains the source.

## Rerun the supporting studies

Use a separate checkout of the [public solver at the pinned revision](https://github.com/philippbogdan/sphere-on-a-torus/tree/376f20bda091acee109abd183bc4684080288fc9), following its [reproduction guide](https://github.com/philippbogdan/sphere-on-a-torus/blob/376f20bda091acee109abd183bc4684080288fc9/docs/REPRODUCE.md):

```sh
python -m polarswe.reproduce --help
python -m polarswe.reproduce refs
python -m polarswe.reproduce diagnostics accuracy mpas series --highres
```

The `diagnostics` stage includes the restart and twin studies; `accuracy`, `mpas` and `series` supply the resolution and time-series comparisons. These broader stages take hours and write into the solver checkout's `data/`. The original records bundled here are their checkable evidence; these supporting studies were not rerun as part of the short check above.
